---
name: implement
description: Use after the slices exist. Builds exactly one slice — the one named, else the next whose blockers are done — runs it, ticks its Done-when boxes, commits. One slice per window; open slices can run in parallel, one window each.
---

Read `builds/<NN>-<slug>/slices.md` first (first argument picks the folder, second the slice; else the only folder, else ask). **Open** slices are those whose **Blocked by** are all done — done means audited *merge*. Take the one named, else the first open. If that slice already has an **Audit:** line with *fix first*, the work is that list in `audits/<NN>.md` — nothing else, each fix the smallest edit that closes its item (one that would add a new block, file or behaviour is a new slice: say so under the item, skip it); when done, tick any box a fix made true, replace the Audit line with **Fixed:** the fix commit — `audits/<NN>.md`, and say run `/audit` again; the run, screenshot and commit rules below still hold. Name the others: each is its own window, `/implement <folder> <NN>`; if more than one is open, work on a branch — `git worktree add ../<slug>-<NN> -b slice-<NN>` — so windows never overwrite each other. Then read `spec.md` — its Implementation and Testing decisions are the rules, its Open ones hold until someone says otherwise — and whatever code exists, in the project root, the folder holding `builds/`. An earlier audit's **Later** list is not this slice's work; an item in lines you change anyway may come along, said under **Chosen:**.

Before any code, say in plain words, under ten lines: what you will make, what it looks like from their side, the exact command or click that starts it, how each **Done when** line — on a fix-first slice, each item on that list — will be tried, then start. No check-in: the slice was agreed in `/slice`. Stuck later: one question, two or three choices, your pick.

Build this slice only — nothing for later slices, no "while I'm here" extras. Smallest thing that makes every Done when line true; install nothing the spec did not imply — a tool only the checks need is allowed, say so. If the spec has a **Look** heading, match it. Where the spec's Testing decisions name a seam this slice touches, write that check first, from outside, then the code that passes it. A check that cannot be made from outside: say so, never fake one.

Run it the way they would — the real command, the real click. Try every Done when line yourself, as a person would: something in the code they cannot reach does not make a line false. Tick a box in `slices.md` only after you saw it pass — a check you ran that covers the line counts; a box you could not try stays open with one line saying why. A line that cannot be made true as written: build what it meant, leave the box open, say why — the audit corrects the line. Anything the spec did not foresee: smallest reasonable choice, one line each under the slice starting **Chosen:**.

Finish by adding under the slice **How to run:** the command, and **Files:** what you made or changed; if it has a screen, take a screenshot of what this slice added — on a fix pass, of the behaviour that changed — one per state it added, look at it yourself, and put it in your message so they see it before audit. Commit the code, `slices.md` and anything still untracked under `builds/`, with the slice number and title as the message, and `— fix first` after it on a fix pass. Stop and say: run `/audit` in a new window before merging or starting the next slice.
